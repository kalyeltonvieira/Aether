# Avaliação experimental do pipeline API

`benchmarks/phase9/phase9_api.py` executa 30 seeds de um fluxo real no `TestClient`: autenticação token de teste e CSRF, criação de 12 entidades, inserção de fatos, regra, consulta aberta, segunda consulta do mesmo padrão (cache), explicação/prova, remoção, reconsulta, leitura do histórico e reinicialização/recomposição. Cada seed compara bindings e fato removido com um oráculo de arestas explícitas independente. Os dados são fixtures sintéticas temporárias, removidas ao fim do seed e não correspondem a uso de produção.

Medição mais recente após as correções de portabilidade Windows (`80b8f83`): 20 seeds de calibração e 10 de holdout, com **30/30 oráculos corretos**. Os hashes SHA-256 das 16 fontes API registrados no JSON coincidem com os arquivos do checkout medido. No Linux ARM64/CPython 3.12.3, mediana do pipeline completo foi 457,3 ms na calibração e 466,7 ms no holdout; P95 observado, 501,8 ms e 499,1 ms; CPU mediana, 420,4 ms e 431,1 ms; reinício mediano, 48,9 ms e 50,0 ms. O artefato [`results/evolution/phase9_api_portability_final.json`](../../results/evolution/phase9_api_portability_final.json) registra hashes, ambiente, RSS high-water global, requests/status e dados completos. `phase9_api.json`, `phase9_api_typed.json`, `phase9_api_final.json` e `phase9_api_branch_final.json` permanecem preservados como execuções anteriores.

**Escopo da medida:** API ASGI in-process, serialização JSON, autenticação, core Python e filesystem temporário no hardware/SO da execução. Não inclui RTT de rede real, navegador, login no provedor OAuth, concorrência de produção, latência por usuário, startup cold ou throughput máximo. Reutilizar esses tempos como SLA seria incorreto. A funcionalidade é também validada por testes de contrato, e o fluxo de browser isolado corre como E2E na CI; não confundir o benchmark API in-process com esse fluxo visual.
